2:55 Chapter 06 — How it works

One pipeline in, one pipeline out.

Corpus — local, one-time

  1. YouTube captions pulled via youtubei.js, cached in-reposeeding never touches YouTube again
  2. Chunked to ~400 tokens with exact start times preserved
  3. Written to Neon Postgres — the source of truth
  4. Embedded into two Qdrant collectionsone per embedding space: gemini + openai

Serving — per request

  1. Embed the question in the active provider’s space
  2. Qdrant top-k search, workspace-filtered
  3. Hydrate hits from Neon — the leak guarda vector whose row is gone cannot be served
  4. Below threshold? Abstain honestly
  5. Stream: sources first, then tokens
3:30 Chapter 07 — Decisions, and why

Boring architecture, sharp edges filed off.

Postgres is the truth; Qdrant is only an index

Every vector hit joins back to Neon before it can be shown. Stale index entries and half-failed deletes fail closed instead of leaking.

Two embedding spaces, seeded up front

One PROVIDER flag flips chat and embeddings together — the dev→submission provider switch needs no reindex and cannot mix vector spaces.

A startup assertion refuses to serve

If the configured embedding model doesn’t match its collection, the app won’t boot. Wrong-space cosine scores look plausible and fail silently; this fails loudly.

workspaceId on every table, day one

Stage 3 is multi-tenant SaaS. Retrofitting tenancy is brutal; carrying one column is cheap.

Stack: Next.js App Router on Vercel · Neon Postgres + Drizzle · Qdrant · Vercel AI SDK (OpenAI / Gemini) · Upstash. Five vendors, no more.

An open LLM endpoint is a free proxy

Per-IP sliding-window limits shape organic traffic; a hard global daily cap bounds liability, because abusers rotate IPs. Worst case is a politely disabled demo — never a surprise bill.

Deliberately not built (Stage 1 discipline)

Hybrid search, reranking, MMR, query rewriting, semantic chunking, the eval harness. Each deserves a measured before/after — not a deadline-week guess.

4:30 Chapter 09 — Where this goes

From demo to benchmark to product.

Stage 2 — retrieval depth, measured

A ~50-question eval set written first; then hybrid search, reranking, query rewriting, MMR, and a chunking experiment — each landing with a before/after number, ending in a published benchmark table. The abstention threshold gets tuned against the eval set instead of by hand.

Stage 3 — the SaaS

Auth and orgs, user-triggered ingestion with progress and retries, deletion that removes vectors with the video, an embeddable widget, API keys, analytics. The tenancy column every table already carries is the down payment.

The same engine generalizes: any long-form educational channel becomes a citable, searchable reference — with the creator credited on every answer.
